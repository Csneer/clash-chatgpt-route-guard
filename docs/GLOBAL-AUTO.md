# GLOBAL Stable Auto

在 Clash 的 GLOBAL 中选择 `GLOBAL Stable Auto`，即可启用本机到节点的自动质量管理。支持 Clash Verge 与静态 YAML 的系统 Mihomo。手动选择其他 GLOBAL 成员或改成 rule/direct，服务停止探测和切换。独立的 ChatGPT 链式代理及其首跳不受管理。

## 选路策略

- 当前节点每轮测 3 次本机到代理服务器端口的 TCP 握手，记录中位数及抖动。多地址域名会尝试可用地址，单个无效 AAAA 不直接判整节点故障。
- 再通过当前代理做两个 HTTPS 204 小请求，**两项都成功才算稳定**。只成功一项仍可记录为暂时可转发，但不能成为稳定候选；HTTP 状态异常或证书错误不会被当成网络故障自动切换。
- 稳定节点还必须满足 `jitter_ms <= 250` 和 `max_tcp_ms <= 800`。每个节点保留最近 1 小时内最多 60 次独立观测，状态中记录可用率、稳定率、连续稳定次数、超时率、延迟、抖动和评分。当前节点连续 3 次质量退化后启动候选扫描；最近 5 分钟内最多 6 次周期观测中累计 3 次硬故障或质量退化，也会确认故障，避免异常类型交替时不断清零。
- **主动择优必须改善至少 100 ms**，候选必须通过实时完整检查，并且当次抖动调整后的延迟分数更好；候选在独立 Mihomo 中复测，切换前再次确认当前节点。当前节点正常时，不会因很小的延迟差异换出口。
- 当前节点与隔离候选即使 TCP 采样失败，也会继续执行真实 HTTPS 转发检查。HTTPS 两项成功则记录为 `unstable-tcp`，不会直接判为断网；TCP 采样质量仍参与稳定性判断和正常择优。
- 连续两轮实际转发网络故障后进入故障切换，不要求新节点快 100 ms。已确认故障后，必须两个独立定时采样稳定才清除故障证据；同轮切前复查的一次成功不足以取消已确认的切换。首个稳定周期返回 `recovery-confirming` 并暂缓切换。手动改选、模式或配置变更、成功切换会清理窗口，过期证据也不会继续参与判断。
- 未达稳定门槛的节点冷却 10 分钟；本机与示例配置每批扫描 2 个节点，并发 2 个。健康期保留一个近期稳定备用复测槽和一个轮转槽，持续覆盖其余节点。确认故障后先复测新鲜缓存备用，成功立即切换，不等待库存扫描；没有通过复测的缓存且仍有复测预算时再扫描。故障扫描优先复查近 10 分钟曾稳定且配置身份一致的节点；旧记录只安排复测，不能直接入选。
- 正常择优与仅质量退化时，候选必须新鲜、未冷却且稳定。**确认当前节点实际转发硬故障时，优先复测完整稳定候选；若没有通过复测的稳定候选，允许有真实 HTTPS 204 成功的部分可用节点临时接管**，此时质量冷却不阻挡新鲜可用证据。最新结果全部转发失败、配置身份不符或过期的节点不能借旧成功记录入选。候选再按近期评分和当次延迟排序；`candidate_rechecks: 3` 表示每轮最多复测 3 个候选，某个候选失败会继续下一名。每轮最多一次线上切换事务；切后验证失败最多回退一次，回退保留原节点的故障计数。
- 硬故障恢复要求初测、隔离复测和切后实际代理检查中，**同一个 HTTPS 检查目标持续返回预期的 204**。不同目标交替成功不能拼成恢复证据；切后全部失败或只剩另一个目标成功会回退。若同一目标仍能访问、但部分 HTTPS、TCP 采样或抖动未达稳定门槛，则留在已恢复转发的新节点，质量退化计数从 1 开始，后续继续观察和择优。旧状态无端点明细时必须重新积累实际证据，不能替部分可用候选证明初测成功。正常主动择优与仅质量退化仍要求切后稳定。
- 本机与示例配置每轮完成后 15 秒再运行，库存与故障决策间隔为 15 秒。主动择优仍每 10 分钟一次，择优后保持至少 10 分钟、每小时最多 6 次，手动改组内节点后保护 120 秒。确认硬故障可绕过普通保持期和每小时择优额度，但真实切换尝试仍间隔至少 30 秒。
- 本机 DNS 最多等待 2 秒、TCP 总预算 3 秒、两个 HTTPS 检查并发且各限 3 秒。在隔离进程正常启动退出且已有可用缓存备用时，两轮确认加备用复验及切后检查的测试时间模型约 63 秒；正常探测更快。若备用也失败、需要更多扫描、共享锁被占用、探测进程启动缓慢或控制器响应不确定，恢复会更久，不构成严格 60 秒 SLA。

候选是普通 SS 节点，支持无插件和内部 obfs 插件，排除 `Codex-*`、链式依赖、动态组和接口绑定节点。HTTPS 检查只确认代理能转发，不用 ChatGPT 直连耗时排名。TCP 握手不是吞吐量测试，也不等同于完整流式业务稳定性。

## 全量统计和评分

所有符合自动组条件的节点都进入轮转库存，本机每批 2 个、并发 2 个；不通过反复切换线上出口来测速。一个完整覆盖周期受节点数量、超时及冷却影响，不承诺每分钟全测一遍。TCP 地址重试共享 `tcp_samples × tcp_timeout_seconds` 连接时间预算；DNS 在可超时的独立进程中解析，HTTPS 并发执行，避免多个超时串行叠加。源码兼容默认参数保留旧值，部署时应显式使用示例中的快速恢复参数。

`inventory_scan_seconds` 控制库存巡检间隔，`candidate_max_age_seconds` 默认 300 秒，过期记录不能成为切换候选。节点配置身份或测量策略变化后重新积累历史，旧格式历史不冒充独立观测。只有周期首测及库存巡检可增加观测，且同节点至少间隔 60 秒；候选复测、切前复查、切后验证不增加独立次数，同次观测发生失败会保守保留。

健康备用不足两个时，同节点身份、最近 300 秒成功的旧记录可以占用一个优先复测槽，帮助配置更新后尽快重新准备备用；它必须通过新参数下的完整探测才能成为候选，旧评分不会复用。失败、身份变更、过期或冷却中的提示不享有优先权，其余节点仍按轮次覆盖。

评分是 0–100 的选路偏好分，**不是可用率的百分比或未来稳定保证**。最新完整探测占最多 80 分（当前可用 50、当前稳定 20、TCP 延迟 7、抖动 3）；最近 5 分钟的可用率、稳定率和超时情况只贡献其余 20 分，按 90 秒半衰期衰减。最新结果本身随年龄衰减，失败或超过 5 分钟的旧结果得 0 分。超过 5 分钟的诊断历史不参与评分，历史高分不能掩盖当前故障。TCP 延迟以 800 ms、抖动以 250 ms 归一化评分，实际可选资格仍使用配置阈值。

“持续稳定”只是近期观测标签，至少需要最近 5 分钟内 3 次独立观测、跨度 120 秒、连续 3 次稳定；不作为硬门槛，也不优先于当前评分。故障恢复或正常择优都允许采用初测和切前复测稳定的新节点；当前健康时仍必须满足 100 ms 改善。节点一度失败后，正常巡检仍保留 10 分钟冷却；已确认当前故障时，允许对超过 120 秒未复测的冷却节点做隔离恢复检查，避免曾经失败的记录阻挡当前已经恢复的节点。硬故障期间，已有新鲜真实转发成功证据的冷却节点可以直接进入复测；最终仍须通过三阶段相同目标验证。

`global-auto status` 的 `inventory` 返回全部节点状态和排名字段，`coverage` 显示总数、已测、新鲜、稳定、待测、冷却及可选数量。`state.nodes` 保存每个节点的历史用于复盘。读取 status 不发公网探测或切换。

## 配置与服务

依赖 Python 3.8+、PyYAML、curl 和 Mihomo。桌面示例配置：[global-auto.example.yaml](../config/global-auto.example.yaml)。默认读取 `~/.config/clash-guard/global-auto.yaml`，状态路径由 `state_dir` 指定。核心代码是 `src/global_auto.py`。

`config_source: verge`（默认）校验活动订阅的 `profile_script` 与 `profiles_index`。`config_source: static` 使用实际 Clash YAML 和运行时选择器进行校验，不需要这两个文件；系统服务配置与安装步骤见 [服务器部署](GLOBAL-AUTO-SERVER.md)。`controller_tcp` 非空时使用指定的回环 `host:port`，否则使用 `controller_unix`；控制器 secret 从实际 Clash YAML 读取，不写入启动参数。

`install.sh` 安装程序和示例配置，不自动安装或启动这套桌面用户服务。桌面部署需将 `systemd/global-auto.service` 和 `.timer` 放到 `~/.config/systemd/user/`，将 launcher 指向已安装的 Python 模块路径，并设置所有绝对路径。活动订阅的 JavaScript 通过 `rewrite_script()` 注入该组；加载前必须验证脚本增量语义、`mihomo -t`、当前模式和既有选择，保存 0600 备份。

```bash
systemctl --user daemon-reload
systemctl --user enable --now global-auto.timer
global-auto status
journalctl --user -u global-auto.service -n 20 --no-pager
```

只检查状态可使用 `global-auto status`；`check` 会执行自动策略。暂停可直接选另一个 GLOBAL 节点，或停止 `global-auto.timer` 和 `global-auto.service`。服务是 oneshot，定时器等待时 service 显示 inactive 属于正常状态。

`state.evaluation` 记录最近一次扫描名单、优先复查名单、`stable_candidates`、`usable_candidates`，以及逐一复测结果；复测和切后检查的 `successful_endpoints` 是成功检查目标的索引，切后 `required_endpoints` 记录初测与复测共同成功的目标。故障期间每轮都会记录动作、当前节点和失败计数；`candidate-unstable` 表示有限次数复测未通过当时适用的稳定性或共同端点要求，`no-stable-candidate` 表示存在新鲜可转发记录但没有符合当前门槛的候选（例如仅质量退化时的 partial），`no-candidate` 表示本轮没有可用候选。以上原因均不等于被 100 ms 择优门槛阻挡。`coverage.eligible` 仍表示正常择优的稳定候选数量，不包含硬故障时可以复测的部分可用节点。

隔离候选的进程校验超时记录为 `probe-timeout`，刷新该候选为不可用并继续预算内的下一候选，避免一个无法启动的探测进程保留旧成功记录、反复阻挡其他备用。

运行中的切换只 PUT `GLOBAL Stable Auto` 选择器，使用 Mihomo `profile.store-selected` 缓存保存选择，不重启核心、不删除现有连接。已有长连接继续原路径。订阅刷新会重新生成该组；如果换到另一份订阅脚本，守护器暂停，需要重新核对配置路径。

与 `global-egress-lock` 共用 run/mutation/probe 锁，绑定器默认忽略 `GLOBAL Stable Auto`。历史显式节点绑定仍属于节点配置的一部分，不会由自动组撤销：其入口失效时该节点冷却，自动组选择其他可用节点。自动模式不保证固定公网 IP，保留手动固定出口模式的独立语义。

控制器写入结果或回滚不确定时，`pending` 留存并暂停进一步切换。先核实实际组选择与状态，再处理；不能无条件清空 pending。配置、profile 或用户选择在探测中变化会使当前评估失效。

## 应用代理边界

GLOBAL 自动组选路管理 `business_proxy` 对应的本机 Clash 路径。应用或账号绑定的独立外部代理可能绕过这条路径，其故障恢复需要应用自身支持。本仓库不安装或配置 Codex Proxy 的账号代理切换功能。

ChatGPT GET 返回 401/403/405 等 HTTP 响应只证明该次隧道和 TLS 已建立，不是流式业务成功。选路改变不重放已经开始的流，新连接采用切换后的路线。

## 验证

`tests/test_global_auto.py` 覆盖 99/100 ms 边界、高抖动排除、稳定候选要求全部 HTTPS 成功、当前与候选实际转发覆盖 TCP 采样失败、硬故障 partial 三阶段共同端点、交替端点拒绝、旧记录缺少实证、质量冷却绕过边界、混合故障窗口与恢复迟滞、候选复测预算、竞态、回滚和 PUT 回复丢失，并使用 loopback TCP 验证握手。`tests/test_global_auto_native.py` 使用真实隔离 Mihomo controller 检查仅 managed 选择器改变、重启后选择持久化、第二候选恢复、partial 恢复与回滚，以及 rule/direct/手动选择不干预。测试使用虚拟故障与确定性探测结果验证决策，不切换生产路由，也不代表公网实际恢复耗时。

静态 YAML + TCP 控制器运行同样的选择与恢复回归，并验证控制器认证、实际配置一致性、配置变化时中止切换。候选进程超时分别覆盖缓存复测继续下一名和库存扫描保留其他节点结果。
